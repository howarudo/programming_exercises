# Programming exercises

My practice repo for DSA and competitive programming, in Python.

- `neetcode_150/README.md` tracks progress by NeetCode 150 topic. It mixes LeetCode and AtCoder ABC problems.
- `neetcode_150/<NN_topic>/<NN>.md` holds the solution for each problem.
- `working_dir/run.py` is where I write the problem I'm currently solving.
- `template/` holds my starter templates.

## Hints

When I ask for a hint, read my current code in `working_dir/run.py` first, find the specific gap or bug, and reply with **one very small hint phrased as a question**.

- Don't give the fix, corrected code, or a full explanation unless I ask for it.
- If there are several bugs, aim the question at the one I should look at next, or at a shared root cause.
- Keep it to one or two sentences, based on my actual code, not a generic tip.

## Problem recommendations

When I ask for problems to practice in a topic:

- Recommend 2–3 well-known competitive programming or DSA-classic problems (AtCoder ABC D/E/F, LeetCode Medium/Hard), each with a link. Only suggest problems you're sure exist with that ID and title.
- For each, name the technique it teaches and how it builds on what I've already solved (check `neetcode_150/README.md`). Don't spell out the solution.
- Give a recommended order, and mention a stretch problem if it's worth it.
- Point out core NeetCode 150 problems in the topic I haven't done yet.
- If a topic is too basic to go deeper, say so plainly and tell me when to move on.
